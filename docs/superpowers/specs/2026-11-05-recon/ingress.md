# Character-sheet ingress button (stock / ChonkyCharacterSheet / EllesmereUI) and the default outfit icon (coat hanger -> fileID 132724)

## Summary
The default icon change is small. The new default is computed and never stored, so no saved data moves. Once `NS.Constants.DEFAULT_OUTFIT_ICON` is a number, the window rows, the bar and the broker already route a fileID to their cropped, edged item-art path. What is left is retiring the gold tint, which means the `of.sheet.button` token, `SHEET_BUTTON_TINT` and Broker's `idleIcon` tint, and fixing about seven tests that assert the glyph or the tint.

The sheet button is the real work. Stock and Chonky both draw Blizzard's own PaperDollSidebarTabTemplate tabs; Chonky adds one more of its own, `MyTransmogButton`, built by hand from the same textures. So one hand-built tab (TabBg + Icon + Hider + Highlight from `Interface\PaperDollInfoFrame\PaperDollSidebarTabs`, 33x35, anchored BOTTOMLEFT to PaperDollSidebarTab3's BOTTOMRIGHT +4) matches both sheets. EllesmereUI's sheet uses text-only labels: 64x25 frames, EUI font at size 10 with no flags, white at 0.6 alpha idle, 1.0 on hover, the `ELLESMERE_GREEN` accent when active, no background or border. Our button there should become such a label stacked above `EUI_CharSheet_Equipment`.

Standards: drawing the host's look instead of the skin breaks skinning-§1/§9, whose exception list is closed. The owner must either ratify a register row or change the standard upstream. Either way `Kit.skinValues` rows are needed, and the sheet button leaves `Kit.skinSwitch.surfaces`.

## Cross-repo
LibKa0s needs no code change: ph:coat-hanger stays in the shipped set under "LibKa0s icons: all". The upstream WowAddonStandards repo changes only if the owner takes the standard-change route instead of a local deviation: a new skinning-§9 exception class, e.g. "host-matched ingress controls placed in another frame's tab strip draw that host's look". If that is wanted, the kit could also gain a category for Interface/PaperDollInfoFrame/PaperDollSidebarTabs. Neither ChonkyCharacterSheet nor EllesmereUI is modified; we only read their frames and fields (PaperDollSidebarTab3, EUI_CharSheet_Equipment._text, EllesmereUI.ELLESMERE_GREEN).

## Risks
- Standards: a sheet button that draws Blizzard's or EUI's look instead of the owner skin breaks skinning-§1 ('every visual element … through the facade'; 'the stock look is a skin, never a host switch') and skinning-§9 (closed exception list). Per CLAUDE.md this must be surfaced and decided: either an accepted-deviation row in docs/ARCHITECTURE.md -> Documented deviations (Rule 'skinning-§1/§9', what differs, why: matching the neighbouring host tabs, decided date, re-check trigger) or an upstream standard change. It must not be done silently.
- The LibKa0s icon rule (window icons cropped >=0.07 and edged with S.IconBorder fromSkin) is replaced on the button by Blizzard's TabBg frame. That is the same deviation and should be named in the same row.
- test_skin_switch fails if the button stays declared, and test_skin_values fails on the typed texture path and EUI alpha literals unless Kit.skinValues rows carry a cause id. Both need the deviation id first.
- The icon's size and position inside TabBg cannot be verified headless. 30x30 CENTER (Chonky's precedent) and 33x35 BOTTOM 1,-2 (the template) look different with a full-bleed item icon, so it needs a client smoke on all three sheets.
- Chonky centres the tab row assuming #PAPERDOLL_SIDEBARS+1 tabs (characterSheet.lua:1538). Our extra tab after Tab3 makes the row about 18.5 px right-heavy. We must not re-anchor Chonky's or Blizzard's tabs (they are other addons' frames, it would fight Chonky, and it risks O29 overlap), so the off-centre row is accepted unless the owner wants otherwise.
- EUI: the label sits above Equipment, in the gap between the level line and the label row. A different EUI font, scale or locale (longer 'Equipment' or 'Outfits' text) may crowd it. The font comes from Equipment._text at each placement, so an EUI font change only shows after the next sheet open.
- EUI first-open ordering: the labels are built from a CharacterFrame OnShow hook after ours. recheckSheet already re-places on the next frame when Kind changes, and applyLook must run there too, or the first open shows the tab look floating over the EUI sheet.
- Taint: low. The button is insecure, parented to CharacterFrame, anchored to unprotected frames, and nothing is written into Blizzard or EUI tables. No hooksecurefunc on PaperDollFrame_UpdateSidebarTabs is needed. Show/Hide stay legal in combat, as today.
- Fewer skin choices: players who liked the gold accent hanger under Ka0s Default lose it, and the button no longer changes with the skin.
- 132724 is an item-armour fileID. If a player explicitly picks 132724 in the icon browser, that outfit becomes indistinguishable from the default. This is cosmetic only, with no data impact.
