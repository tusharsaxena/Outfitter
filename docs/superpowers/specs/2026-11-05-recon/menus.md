# (1) Outfit context menu: nested submenus close the whole menu. (2) The window header's gear icon is bigger than the close X.

## Summary
(1) The parent menu doesn't close because of an addon handler. LibKa0s's W.ContextMenu (Widgets minor 21, vendored v1.86.0, which is also the newest LibKa0s tag) is a single shared frame that deliberately has no sub-menus. NS.OpenMenu's showLevel (core/WidgetsSetup.lua:128) fakes a submenu by reopening that one frame with the child's rows, so the parent is already gone once a submenu opens. The library also hides the frame before any row's click runs unless the row is keepOpen (Widgets.lua:425), so picking a nested leaf closes everything. Nothing in OutfitMenu.lua calls CloseMenu. To keep the parent visible beside its child (true cascading flyouts), LibKa0s needs a new Widgets minor, then a release and a re-vendor. A smaller fix that touches only this addon: after a nested pick that changes state, reopen the parent level (rebuilt, so labels like "Automation: X" are fresh) instead of closing. (2) The close control is an 18x18 button with 12x12 art (Core.lua:247-248). The gear is an 18x18 button whose texture fills the whole button (SetAllPoints), so it draws 18x18 against the X's 12x12. The fix: centre the gear texture at 12x12 and keep the 18x18 button.

## Approach
PART 1: the menu. There are two layers. Ask the owner which one they want (see the questions).

A. Addon-only fix, shippable now (core/WidgetsSetup.lua plus modules/OutfitMenu.lua). After a state-changing pick inside a nested level, go back to the parent level, rebuilt, instead of closing. Make the stay-or-close choice a row property, written MenuUtil's way so the fallback MenuUtil path behaves the same:
 1. Recorder (newLevel, WidgetsSetup.lua:50-77): give each row `function sub.SetResponse(_, r) sub.response = r end`. Add `level:CreateRadio(text, isSelected, setSelected, data)`, shaped like CreateCheckbox but with a radio flag, so the current choice shows a tick through checkLabel. Record each sub-level's parent (`sub.parent = self`).
 2. NS.OpenMenu: keep `fill` and `anchor` in a local `active = {anchor=, fill=}`. Add `reopenAt(path)`: build a fresh level, run fill again, walk the stored index path (the item indices from root down to the parent level), then showLevel the result. A fresh fill is needed because labels like 'Automation: X', the 'Outfit N (holder)' names and the ticks are captured when fill runs. menuRow passes the path down: showLevel(anchor, level, path), and a submenu row's onClick becomes showLevel(anchor, item, path..{i}).
 3. In menuRow, a nested row (path non-empty) whose response means stay (MenuResponse.Refresh, or the radio default) gets `out.keepOpen = true` and `out.onClick = function() item.onClick() / item.setSelected(item.data); reopenAt(parentPath) end`. Because keepOpen skips the Hide (Widgets.lua:425) and the reopen moves the frame to a new ctx (so `menu.__dd ~= dd` and no stale Populate), the frame never blinks. On the fallback MenuUtil path the same rows return or carry MenuResponse.Refresh, so Blizzard keeps the whole cascade open.
 4. Stop the jump: W.ContextMenu returns the frame, so reopenAt can remember `m:GetLeft()/GetTop()` before the reopen and re-anchor afterwards (`m:ClearAllPoints(); m:SetPoint('TOPLEFT', UIParent, 'BOTTOMLEFT', l, t)`). Optionally do the same in a submenu-row open, so every level stays put. This moves a library-owned frame (only one returned to the caller). If that is judged too intimate, take B instead.
 5. Optional: add a 'Back' row (or a title row with a chevron-left) at the top of each nested level, so the player can go up without picking.

Per-entry classification:
 - KEEP OPEN, back to parent: Key binding None / Outfit N (radio on O.BoundTo, which unbinds the previous holder, so the labels must be rebuilt); Title None / title (radio on rec.titleID; setTitle's 0.5 s timer is unchanged); Automation 'No trigger' and any trigger pick WITHOUT params (radio on rec.trigger.id; the parent label 'Automation: X' and the enabled state of the 'Turn trigger off' and 'Disable outfit in combat' rows change, so going back to the root level reads best); the existing root toggles (unequipOthers, ignoreComparisons, trigger disabled/combatDisabled, Show in outfit bar), which already keep the menu open (WidgetsSetup.lua:102-109).
 - ACT AND CLOSE (they open a dialog, popup or window that the FULLSCREEN_DIALOG menu would otherwise cover): Rename..., Delete (Popups.ShowDelete), Update to current items, Rebuild for <stat>, Rebuild for..., Trigger settings..., Change icon..., and a trigger pick WITH params ('...', which opens TriggerDialog at OutfitMenu.lua:163). These keep today's default (no keepOpen). Under MenuUtil they must return nil or CloseAll.
 - Navigation only: submenu rows and 'More'.
 - Bank moves: owner's call. Suggestion: close, because a move starts a queued item transfer and reports by print. Keeping open is harmless, though.

B. True cascading flyout (the parent stays visible beside the child). This is a LibKa0s change, Widgets.lua minor 23: a row option `submenu = rows` (plus optional `radio`/`selected`). Child frames would be pooled per depth (EnsureMenu generalised to `menus[depth]`) and anchored TOPLEFT to the hovered or clicked row's TOPRIGHT (clamped, flipping left at the screen edge). Opening a sibling hides deeper frames. __OutsideClick would test every shown depth frame (Widgets.lua:497-502). OnHide of depth 1 hides all depths, and CloseMenu hides all. On a keepOpen click in a child, Populate both the child and its ancestors so parent labels refresh. That needs a docs/api/Widgets version doc, a CONSUMERS row, a LibKa0s release, then /dev-copilot:wow-revendor-libka0s here. On the addon side, showLevel would build the whole nested rows tree once instead of replaying it level by level. The keepOpen and radio classification above still applies.

Tests: extend tests/test_outfit_menu.lua. A binding pick sets keepOpen and the next recorded menu is the root with fresh labels and a tick on the bound slot; Delete/Rename/'Trigger settings...'/a params trigger are not keepOpen; a nested pick on a two-deep path (Automation > category > trigger) goes back to the expected level. Update the module header comments (OutfitMenu.lua:6-9, WidgetsSetup.lua:40-44) and docs/test-cases.md.

PART 2: the gear. modules/Window.lua:138-139. Replace `gear.icon:SetAllPoints(gear)` with `gear.icon:SetPoint('CENTER', gear, 'CENTER', 0, 0); gear.icon:SetSize(art, art)`, where `local art = (close and close.icon and close.icon:GetWidth()) or 12`, falling back to 12 = LibKa0s Core.lua:248 CLOSE_ART. Reading the close's own art keeps the two in step without copying a library file-local. Keep the button at 18x18 and the anchor at TOPRIGHT -28,-5, so test_dock.lua:550-560 still holds. Optionally tint the gear grey at rest (0.7, 0.7, 0.72) with a brighter hover to match the X; that is an owner question. Add a test_dock assertion that the gear's icon is CENTER-anchored at the close's art size.

## Risks
- Placement: a reopen from inside a click must use cursor=true (a non-cursor reopen on the same anchor toggles the menu closed, Widgets.lua:763-766), and that moves the menu to the pointer. Re-anchoring the returned frame in the addon reaches into a library-owned shared frame that other Ka0s addons also use. The house rules for library usage (library-stack-§7) may count that as a deviation, so flag it or prefer option B.
- Rebuilding the menu by index path assumes the fill's shape doesn't change from the pick. Today no nested pick adds or removes a root row ('Unequip others' depends on category, not on these picks), but a future conditional row could shift the indices. Fall back to root when the path no longer resolves to a submenu.
- Keep-open picks must not run anything protected. SetBinding, titleID and the trigger id are DB writes, and the title shows later through AceTimer. The menu frame is insecure FULLSCREEN_DIALOG, so there is no taint risk beyond today's. Bank moves start item moves; leaving the bank state unchanged is fine because the bank rows read NS.Bank.IsOpen at fill time.
- A trigger pick with params opens TriggerDialog. It must stay act-and-close, or the menu (FULLSCREEN_DIALOG) covers the dialog.
- Fallback MenuUtil path: radios default to Refresh, but plain CreateButton callbacks return nil, which means CloseAll. Wrapped onClicks must return MenuResponse.Refresh only where the menu should stay open, and must guard against MenuResponse being nil.
- Option B's library change affects every Ka0s consumer of the shared menu (dropdowns, the test strip's right-click menu, the Broker menu). The existing single-level behaviour must be left unchanged.
- Gear: the close control can fall back to a font-glyph X (no Media 'close' icon, Core.lua:304-311). Then close.icon is nil and the 12 fallback applies. Also NS.Skin.Button may track the texture: check that no skin repaint calls SetAllPoints on gear.icon again (it is noBg/noBorder; SkinPaintControls Button does not re-anchor .icon, as far as I read).

## Facts
- NS.OpenMenu records the MenuUtil-shaped fill into plain tables, then draws one level at a time through W.ContextMenu at the cursor. [core/WidgetsSetup.lua:138-148 (OpenMenu), :128-132 (showLevel calls W.ContextMenu(anchor, rows, {owner=addonName, cursor=true}))]
- A submenu row is just a button whose onClick reopens the shared menu with the child level's rows. The parent's rows are replaced, not kept. [core/WidgetsSetup.lua:119-122 `out.onClick = isSubmenu and function() showLevel(anchor, item) end or item.onClick`. The comment at :40-44 says 'that menu has no flyout, so a submenu's row opens its own rows in the menu's place'.]
- The library hides the menu before a row's callback unless the row has keepOpen. A keepOpen row is repainted afterwards, but only if the same ctx still owns the frame. [libs/LibKa0s/Widgets.lua:410-428 rowOnClick: `if not opt.keepOpen then menu:Hide() end; if dd.onSelect ...; if opt.keepOpen and menu:IsShown() and menu.__dd == dd then menu:Populate(dd) end`]
- Sub-menus are explicitly out of scope for the library today. It is one process-wide frame (FULLSCREEN_DIALOG, parented to UIParent). [libs/LibKa0s/Widgets.lua:32-35 ('no keyboard navigation, no scrolling for a long list, no sub-menus ... each is reachable later without a major bump'); EnsureMenu at :457-533; MINOR = 22 at :108]
- W.ContextMenu with a non-cursor open on the same anchor while the menu is shown toggles the menu closed. A re-open from inside a click must therefore use cursor=true, and that re-places TOPLEFT at the pointer, so the menu jumps. [libs/LibKa0s/Widgets.lua:759-777 (`if m:IsShown() and m._owner == anchor and not opts.cursor then m:Hide()`), placeAtCursor :550-555]
- The outside-click close only tests the one menu frame and its owner anchor, so a second (flyout) frame would count as an outside press today. [libs/LibKa0s/Widgets.lua:497-502 menu:__OutsideClick]
- No OutfitMenu entry calls NS.CloseMenu. The only CloseMenu callers are window/dialog hide paths and the broker. [grep: modules/Broker.lua:106, modules/Dock.lua:176,279, modules/UIDialogs.lua:173. Nothing in modules/OutfitMenu.lua.]
- The LibKa0s repo has nothing newer than the vendored copy, so submenu support does not exist upstream either. [/mnt/d/Profile/Users/Tushar/Documents/GIT/LibKa0s HEAD cad1609 'Release v1.86.0', newest tag v1.86.0; CLAUDE.md pins v1.86.0]
- The nested levels in the outfit menu are Key binding (None, Outfit 1-10), Title (None, titles, 'More' chained every 30), Bank (5 moves, disabled while the bank is closed), and Automation: <name> (No trigger, then a category level, then trigger picks: two levels deep). [modules/OutfitMenu.lua:57-66, 85-96, 110-122, 166-179]
- Only OutfitMenu uses nesting. The Broker menu and the trigger-field add menu are flat, so a showLevel change only affects the outfit menu. [modules/Broker.lua:162-183 (CreateTitle/CreateButton/CreateCheckbox at root only); modules/Dialog_TriggerFields.lua:159-166]
- Without the library, the same fill goes to MenuUtil. Blizzard's MenuUtil cascades natively. A nil or CloseAll response closes the whole tree, Refresh keeps every open menu and re-initialises it, and SetResponse sets a per-element default. [wow-ui-source@297d7aa:Interface/AddOns/Blizzard_Menu/MenuConstants.lua:17 (MenuResponse Open/Refresh/Close/CloseAll); Menu.lua:874-876 (SetResponse); Menu.lua:2233-2250 (nil/CloseAll -> CloseMenus, Refresh -> SecureReinitializeAll); 11_0_0_MenuImplementationGuide.lua:131 (CreateRadio)]
- The tests record W.ContextMenu calls in ctl.menus. A submenu click shows up as a new recorded menu, and toggles assert keepOpen. [tests/dialog_scene.lua:72-93; tests/test_outfit_menu.lua:39-45, 180-185]
- The close control is an 18x18 button with its art centred at 12x12, grey 0.7/0.7/0.72 at rest and red on hover. CLOSE_SIZE and CLOSE_ART are file-locals and are not exported. [libs/LibKa0s/Core.lua:247-254, 283-300 (b:SetSize(CLOSE_SIZE,CLOSE_SIZE); tex:SetPoint('CENTER'); tex:SetSize(CLOSE_ART,CLOSE_ART); b.icon = tex)]

[modules/Window.lua:135-143 (gear:SetSize(18,18); gear.icon:SetAllPoints(gear); SetTexture(NS.Icon('settings')); NS.Skin.Button(gear,{noBg=true,noBorder=true})); close at :129-131 (TOPRIGHT -6,-5); screenshot 7.png]
